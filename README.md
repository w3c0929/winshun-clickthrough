# 点击穿透 · Click-through

复刻 [AltSnap](https://github.com/Raymai97/AltSnap) 的 **ClickThrough**：让一个窗口暂时“点不到”——鼠标点击落到它下面的窗口上；窗口同时按设置变淡并留在最上层。再次触发、退出 Win顺，或插件崩溃后下次启动时会恢复原样。

- 插件 ID：`w3c0929.clickthrough`（与插件库条目一致）。

## 关键字与示例

| 关键字 | 作用 |
| --- | --- |
| `ct` / `穿透` / `点击穿透` / `clickthrough` | 列出有标题的窗口；`ct 微信`、`ct chrome` 按窗口/程序名过滤 |

- 列表第一行是当前前台窗口，其余按标题排序；已穿透的窗口会标注“已穿透”。
- **Enter**：对选中窗口切换穿透/恢复（同一时间只保留一个穿透窗口，和 AltSnap 一致；已有穿透窗口时先恢复它，不会把效果移到另一个窗口）。
- **Ctrl+Enter**：恢复当前被穿透的窗口。
- 穿透后，**鼠标悬停、点击、滚轮和键盘**都交给下层窗口：应用穿透的同时就把焦点交给鼠标下（光标不在目标窗口内时用窗口中心）最近的一层窗口，键盘立即可用；之后移动/点击/滚动仍直接作用于下层，不需要先点一下给它焦点。（固定行为，无开关。）
- 下层窗口可能有多层：输入总是属于鼠标位置处、穿透表面正下方的第一层窗口；再往下由 Windows 的点击规则处理。
- 下层窗口打开的**菜单、下拉列表、tooltip**（包括应用自绘的菜单，如 Sublime Text）不会被本插件激活或关闭，鼠标可以正常移动和选择菜单项。
- 默认快捷键 **F2**：按下时对前台窗口切换穿透/恢复（和 AltSnap 默认一致，可在设置里改为鼠标下的窗口），不需要打开 Win顺；也可以改成其他组合键。

## 设置

- **穿透时透明度 (%)**：默认 `85`，明显变淡（不透明度约 15%）；`0` 只穿透不变淡，`100` 完全看不见。
- **切换穿透的快捷键**：默认 `F2`，留空不注册。宿主需支持 `hostHotkeys`（`initialize.capabilities.hostHotkeys`），否则请用 `ct` 命令。
- **只恢复的快捷键**：可选的第二个快捷键，按下只恢复当前穿透窗口，不会对其他窗口开启穿透；留空不注册。
- **操作时在底栏提示**：默认开，用快捷键穿透/恢复时在 Win顺 底栏显示“已穿透/已恢复”，便于确认操作成功。

- **快捷键作用于鼠标下的窗口**：默认关，和 AltSnap 的 `UsePtWindow=0` 一致——快捷键作用于**前台窗口**；打开后改用鼠标下的窗口。
- **最多列出**：查询最多返回多少行，默认 30。

## 运行依赖

- Win顺 ≥ 0.23.0（常驻原生插件，自带 `ClickThrough.exe`；`ui` 和 `elevated` 权限）。
- 不需要 PowerShell、WinForms 或其他运行库；exe 是 .NET Framework 4.x 程序，Windows 自带。半透明覆盖窗口用原生窗口 + DWM 缩略图（Windows 10/11 默认开启）。
- 不依赖 AltSnap，也不需要安装任何额外程序；只用 Win32 API。

## 权限与原因

| 权限 | 原因 |
| --- | --- |
| `ui` | 枚举窗口、读写窗口扩展样式（`WS_EX_TRANSPARENT`/`WS_EX_LAYERED`）、设置置顶，以及让宿主代注册快捷键。 |
| `elevated` | 跟随 Win顺 的管理员权限：Win顺 以管理员运行时，确认一次后本插件也以管理员运行，才能修改管理员权限的窗口；Win顺 普通运行时插件也以普通权限运行，不会弹 UAC。 |

- **以管理员运行前的确认**：声明 `elevated` 的插件，Win顺 不会直接运行插件文件夹里的 exe，而是把它复制到 `%ProgramFiles%\WinShun Elevated Plugins\<用户 SID>\clickthrough`，校验每个文件的 SHA-256 后从副本启动。你在插件卡片上点一次确认即可；**插件文件改动后副本失效，需要在卡片上重新确认**。
- 普通权限运行时，插件改不了管理员权限窗口（UIPI），这是 Windows 的限制；这时把目标程序以普通权限运行即可。

- 本插件声明 `elevated`：Win顺 以管理员运行时，确认后插件也以管理员运行；Win顺 普通运行时插件以普通权限运行。管理员窗口仍受 Windows UIPI 限制。
- 权限声明不等于系统强制隔离；本插件也只做上面这些窗口操作。

## 数据位置

- `WS_DATA_DIR/clickthrough.json`：当前穿透窗口的句柄、原始扩展样式、原始 alpha 和窗口类名，仅用于**崩溃恢复**。正常退出时会恢复窗口并删除该文件。
- 不写注册表、不改剪贴板；为排查问题，日志会记录目标窗口的标题和类名。

## 失败处理

- 目标窗口已关闭或类名变化：不去改它，直接清掉记录。
- 窗口属于管理员权限/其他用户：样式写入失败，列表项与动作都会给出“无法修改（可能是管理员权限）”的提示，不会伪造成功。
- 旧宿主没有 `hostHotkeys`：快捷键不注册，在 stderr 与插件日志里说明，`ct` 命令仍可用。
- 目标窗口以管理员权限运行、而插件以普通权限运行：系统拒绝修改，`plugins.log` 记录窗口类、进程和错误码，结果与动作会提示“无法修改（可能以管理员运行）”。让 Win顺 以管理员运行并确认 `elevated`，或把目标程序改为普通权限运行。
- 插件被强制结束：下次启动时读取 `clickthrough.json`，只有窗口仍在且类名一致、看得出是我们改的样式时才恢复。

## 与 AltSnap 的功能对照

已对齐：

- 切换模式：按一次让窗口穿透，再按一次恢复；**已有穿透窗口时，按键只负责恢复它，不会把效果移到另一个窗口**（一次只保留一个）。
- 透明度：默认 85（AltSnap 原默认 80），`alpha = (255*(100-t)+50)/100`；原本已经透明（layered 且 alpha<255）的窗口不再改透明度，恢复时也不动。
- 样式：加 `WS_EX_LAYERED|WS_EX_TRANSPARENT` 并置顶；恢复时还原 `WS_EX_LAYERED`、原 alpha 和置顶状态。
- 崩溃恢复：状态写 `clickthrough.json`；重启后只在窗口仍在、类名一致且样式仍看得出是我们改的时候才恢复，避免误改别的窗口。
- 窗口消失：清除跟踪状态，下次重新应用。
- 目标选择：热键默认作用于**前台窗口**（AltSnap 的 `UsePtWindow=0`）；可在设置里改成鼠标下的窗口。

额外的兼容处理（AltSnap 没有）：

- **半透明显示与点击分离**：Windows 在 layered 窗口 `alpha > 0` 时，穿透点击只会激活下层窗口，不会传给它的控件（地址栏等）。插件的做法是：把真正的目标窗口设为完全透明（alpha=0，点击完全穿透），再建一个**原生、无边框、置顶、点击穿透的覆盖窗口**，通过 DWM 缩略图按设置的透明度显示目标窗口内容。覆盖窗口按 **DWM 扩展边框（物理像素）**精确对齐，每 25ms 跟随目标的位置/大小；原生窗口没有 WinForms 的非客户区/DPI 缩放，因此不会出现放大或错位。缩略图失败时退回“目标窗口半透明、点击只激活下层”的旧行为。
- **键盘和鼠标一起交给下层**：穿透应用时立即激活鼠标下（或窗口中心）最近的一层窗口，键盘不需要等鼠标移动才生效。
- **滚轮不拦截**：滚轮和普通窗口一样由系统直接发给鼠标下的那个控件，不手动转发，因此浏览器、编辑器、列表等所有应用都能正常滚动（包括子控件和触控板平滑滚动）。
- **任意应用的弹层保护**：鼠标位于下层窗口打开的菜单、下拉列表、tooltip 上时（按窗口样式识别，包括无标题的、应用自绘的弹出层），不激活任何人，弹层保持打开；传统的 Win32 菜单在打开期间对所有悬停位置都不激活。任务栏/桌面弹层同理。
- **覆盖窗口不抢最上层顺序**：覆盖窗口每次显示只置顶一次，之后只更新位置和大小，不再每帧抢占 topmost，因此后出现的置顶弹窗（例如应用自绘的菜单）不会被它压到下面。

未复刻：

- **Hold 模式**（按住快捷键期间才穿透，松开恢复）：Win顺 插件协议只提供按键“按下”通知，没有按键释放事件。用切换模式代替。
- AltSnap 的鼠标手势/拖拽触发：本插件只提供 `ct` 查询和宿主热键；鼠标钩子只用于把悬停、点击和滚轮交给下层，并保护下层应用的弹层，不提供拖拽触发。
- 物理按键序列去抖、按键释放安全网：热键的按下由 Win顺 宿主触发，插件按通知切换。

## 构建

`ClickThrough.exe` 由同目录的 `ClickThrough.cs` 单文件编译，不引用第三方库：

```powershell
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:exe /codepage:65001 /out:ClickThrough.exe ClickThrough.cs
```

`tests/exe_protocol_test.ps1` 用 JSON-RPC 走一遍 initialize/query/action/shutdown；`tests/exe_toggle_test.ps1` 启动一个测试窗口，验证扩展样式确实写入并恢复；`tests/exe_hook_test.ps1` 验证真实点击穿透到下层；`tests/exe_menu_test.ps1` 验证多层窗口、键盘立即移交、经典菜单与应用自绘弹层不被关闭、覆盖窗口不抢最上层；`tests/exe_wheel_test.ps1` 用 `tests/WheelSink.cs`（测试时由 csc 编译）验证滚轮直接到达鼠标下的子控件。旧的 `main.ps1` + `WinShun.psm1` 是脚本版实现，当前 manifest 不再引用，保留作参考。
