# 鼠标穿透 · Click-through

让一个窗口暂时“点不到”——鼠标点击落到它下面的窗口上；窗口同时按设置变淡并留在最上层。再次触发、退出 Win顺，或插件崩溃后下次启动时会恢复原样。

- 插件 ID：`w3c0929.clickthrough`
- 当前版本：1.8.2

## 功能一览

- 鼠标点击、滚轮与键盘落到下层窗口。
- 窗口按设置变淡，位置不变，仍在最上层。
- Ctrl+Alt+滚轮调节透明度，只变淡、不穿透。
- 菜单、下拉列表与 tooltip 保持打开。
- 插件退出或崩溃后恢复原样。

## 穿透与恢复

```mermaid
flowchart LR
    A[按 F2] --> B[目标窗口完全透明]
    B --> C[覆盖窗口显示缩略图]
    C --> D[输入交给下层]
    D --> E[再按 F2 恢复]
```

覆盖窗口是原生置顶窗口，点击穿透。它每 25ms 跟随目标窗口的位置和大小。

## 快捷键与透明度调节

| 操作 | 结果 |
| --- | --- |
| F2 | 对前台窗口切换穿透/恢复 |
| F10 | 恢复穿透窗口，或鼠标下调过透明度的窗口 |
| Ctrl+Alt+滚轮向上 | 透明度加 10%，更淡 |
| Ctrl+Alt+滚轮向下 | 透明度减 10%，更清晰 |
| 滚回 0% | 恢复原样，清除记录 |
| 调到 100% | 视觉不可见，内部 alpha=1，点击仍属于该窗口 |

调节只改变视觉，窗口仍可正常点击操作。

## 默认设置

| 设置 | 默认值 |
| --- | --- |
| 穿透时透明度 | 85 |
| 切换穿透快捷键 | F2 |
| 只恢复快捷键 | F10 |
| 调节修饰键 | Ctrl+Alt |
| 每次步进 | 10% |
| 快捷键作用于鼠标下窗口 | 关 |
| 底栏提示 | 开 |
| 最多列出 | 30 |

## 兼容处理

| 场景 | 行为 |
| --- | --- |
| 弹层菜单，含自绘菜单 | 不激活，菜单保持打开 |
| 多层窗口 | 输入属于鼠标下最近一层 |
| 滚轮 | 系统直接路由到鼠标下控件 |
| 后台窗口忙 | 窗口操作在后台线程，不卡鼠标 |
| 恢复焦点 | 不注入按键，焦点交还原窗口 |
| 崩溃恢复 | 读取 `clickthrough.json`，恢复窗口与透明度 |

## 关键字

| 关键字 | 作用 |
| --- | --- |
| `ct` / `穿透` / `鼠标穿透` / `clickthrough` | 列出有标题的窗口；`ct 微信`、`ct chrome` 按窗口/程序名过滤 |

列表第一行是当前前台窗口；已穿透的窗口会标注“已穿透”。

- **Enter**：对选中窗口切换穿透/恢复（一次只保留一个穿透窗口）。
- **Ctrl+Enter**：恢复当前被穿透的窗口。

## 安装与权限

- 依赖 WinShun 0.23.0 或更高；`ClickThrough.exe` 为 .NET Framework 4.x 程序。
- 权限：`ui`（枚举窗口、修改扩展样式、置顶、宿主代注册快捷键）、`elevated`（跟随 Win顺 的管理员权限）。
- 声明 `elevated` 的插件需在插件卡片确认一次；exe 改动后受保护副本失效，需要重新确认。
- 数据：`WS_DATA_DIR/clickthrough.json`，仅用于崩溃恢复。不写注册表、不改剪贴板。

## 失败处理

- 目标窗口已关闭或类名变化：清掉记录，不改窗口。
- 目标窗口以管理员权限运行而插件权限不足：提示“无法修改”，不伪造成功。
- 旧宿主没有 `hostHotkeys`：快捷键不注册，`ct` 命令仍可用。
- 插件被强制结束：下次启动读取 `clickthrough.json`，只有窗口仍在、类名一致时恢复。
